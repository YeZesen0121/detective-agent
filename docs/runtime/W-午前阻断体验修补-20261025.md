## 修补结果

1. failed 且停止原因为 model/search/read/token/cost/time_limit 时显示“到限未完／本轮已到限，尚未形成报告”，保留原问题，提供只读状态核对，不展示不支持的继续或诱导重发。普通 provider_error 等失败保持原失败口径。有旧报告时到限提示与旧正文并存。按 P 后续明确追加授权，无报告到限页提供“重新开查本案”：复用原问题、新建一轮额度，明确点击才发送 add_budget/previousRunId；available=false 或恢复不完整时禁用，点击也核对最新可用性和原 run 绑定，不强迫换案或重新输入。
2. URL 案卷在当前 session 返回 404 时，页面明确显示“当前会话无法读取此案卷，请使用原会话或新开调查”，优先于所选版本的读取错误。“新开调查”只清除原案 URL，进入新草稿，不自动启动。真实 fixture HTTP 仍返回 404，不显示另一 session 的报告，也不绕过所有权校验。
3. 使用 P 的可选 `newInvestigations`：available=false 时显示服务器 message，允许保存草稿、读取报告；禁用草稿“开查”，提交函数也拦截，附件核对完成后、发 start POST 前再次读取最新可用性。手动核对能力恢复后可由用户显式开查，不自动 POST。没有禁用所有 followups，已有材料解释仍可提交。
4. 新字段缺失沿用旧逻辑。既有 dev-proxy、截图和空模式兼容场景明确模拟旧服务省略可选字段，保留原 start/503 恢复断言；workbench 场景改为核对新服务 unconfigured 时禁开查。
