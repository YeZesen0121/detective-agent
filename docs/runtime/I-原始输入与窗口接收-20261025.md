## 原始输入到调查

- identify、截图提取及多分句/并列/多个问项的 truth/latest 使用 `investigation.scope.grounded.v1` 提议、`investigation.scope.review.v1` 独立语义复核。每次 `purpose=scope`，最多2次，输出上限1600+1200；每次输入 `UTF8(JSON.stringify(messages))+512 <= min(24000, snapshot.remaining.inputTokens)`。均走共享研究预算，不旁路收费门。
- 对象、每条线索、每个目标须绑定 `inputRef` 与实际输入引句。原问题保留，previousScope 的对象/模式/归属不被模型替换；已确认 scope 无新回答仍复用，简单缺对象保持零调用必要澄清。
- 截图 visibleText、claimSuggestions、speakerClues、visibleDates 分别作为用户提供材料进入范围，不能当公开证据事实。关键 uncertainSpans 未明确确认时先问；proceedWithUnknown 或“继续吧”不补字段。确认需要唯一的提议 resolution 和独立 criticalCheck，以及真实回答引句；重复的 true/false 不能过滤否决后通过。
- 全文及相邻回指语境处理确定性，后置“记不清”、远处“可能”不能被短前缀遗漏；独立复核逐 clue 核对 known/uncertain。混合记忆不拼成一份确定故事。三图或描述过长时明确收窄，不静默截断关键输入。
- 初搜包含对象、已确认目标和相关线索，uncertain 仍作为待核对记忆写进 purpose，不冒充事实。有效名称如 Secretlint 不因包含 secret 子串被删；指令型对象无法形成合法查询时受控 failed/invalid_output，不发无对象或空查询。

## 材料驱动查询与窗口

所有后续 query 都须独立 `queryChecks` 明确原范围及未覆盖 goal；显式已答 goal 不能用另一个 gap 抵消，scopeMatches=false 对整对象/别名快路径也有否决效力。用户显式别名可锚定；新材料中的名称或候选需额外 anchors，把 query 文本、当前选中完整证据及可定位引句绑定，不用名称白名单。

新 query 带权威 `context.budgetWindowId`；当前窗口按 tagged 查询的最大实际 batchNo 计批，不以12调用分槽冒充4批。旧未标 tag fixture 只按当前 runId 回退，真实历史由 P 补权威归属。snapshot.used+reserved.searches 与本次已发送数仍约束12调用。四个各1条的跨run批次后不再开第5批；显式新window从批次1起，旧12条未知历史保留，第13条可保存。

## 候选、跨语言与追问刷新

候选名字、译名有实际材料依据。每条确定/不确定线索须经唯一 `candidateChecks.clueChecks`、对应原语引句与关系核对；不要求英文材料逐字包含中文线索，也不再用 raw matchedClues 的字面出现代替语义核验。无引句、重复矛盾复核、截断或 context risk 都不能完成。

保留有硬冲突的其他候选；仅在一个完整匹配者且其他候选有已核对的确定冲突时，身份目标可以收敛。不确定记忆不作硬排除。候选只覆盖独立确定的身份目标，不顺带回答费用、日期等目标；核心 unknown 门禁覆盖所有 answered 路径。

明确同案 followup 的新 run、新查询可以对已捕获 URL 再读一次，追加新捕获并保留旧 checkpoint；同run不重复读，initial/resume原URL去重保留。失败不自动重试，旧 search 未知历史不删除重放。
