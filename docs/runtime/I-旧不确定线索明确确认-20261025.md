## 原反例与实现

旧 uncertain 为“主角是成年男老师”，真实新 saved_followup 为“我确认主角是成年男老师”。原程序两阶段都判 known，仍由旧 softClues 过滤掉，canInvestigate=true 却原样 uncertain。旧报告不可变不意味着新 scope 永远不能确认记忆。

现有两次 scope 模型内增加私有字段：

- 提议 `clueConfirmations:[{uncertainClueIndex,inputRef,quote}]`：旧 uncertain 索引、新 saved_followup/真实 clarification 原句；不允许网页、旧 scope 或 unknown continuation 冒充新确认。
- 独审 `clueConfirmationChecks:[{confirmationIndex,approved,certainty:known/uncertain,reason}]`：对 confirmationTable 独立检查原索引、原文字及新原句指代和当前确信。必须每项唯一、approved=true 且 certainty=known；缺项、重复、越界、拒审或当前仍不确定则整批不发布。

批准后只把旧数组的**原文字**加入新 known、移出新 uncertain；不以同义字符串代替旧文字，不改对象/目标/地区/时间/模式/查询参照等字段。重复新 known 提取仍不能替代明确确认，普通新增线索的局部不确定门保持。确认与同项新 uncertain 或旧 known 降级发生矛盾时整批拒绝；多项确认中一项失败也不部分捡回。旧 scope 对象不修改，P 用现有来源授权与版本门保存新 scope。

独审复现并关闭一项 Important：完整确认句“我之前不确定，现在确认主角是成年男老师”会被历史不确定词误挡，而窄引句可过。已先 RED，再将确认确定性明确交给独立复核的当前 certainty 判断，区分过去与当前，不对完整确认引句做任意关键词否决。两句完整/窄引句均通过；当前 uncertain 即使 approved=true、独审 false 或缺 certainty 仍拒绝。

known 表示用户当前明确陈述，不表示外部事实已证实；后续候选仍须依据实际来源逐线索核验。没有增加模型调用或跳过独审。
