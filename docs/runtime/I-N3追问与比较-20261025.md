## 追问

`routeFollowup(FollowupInput, InvestigationServices, AbortSignal): Promise<FollowupDecision>` 验证输入及 investigation/version 归属，只返回 explain / research_same_scope / suggest_new_case / needs_budget_confirmation。

明确固定版本回指的解释直接提取该 payload 已保存的 claims、candidates、条件、未知、查询时间和证据引用。没有 claims 的 identify 版本同样能解释保存的候选匹配/冲突/缺失，不编造 claim。过长解释保留限制并提示展开固定报告，不默删条件后增强结论。

其他问题用 `investigation.followup.v1` 分类：仅 `purpose=followup`，本实现至多1次、maxOutputTokens<=1000、输入<=min(24000,交互池剩余inputTokens)。分类只选路由/已有索引；忽略模型新答案，解释始终抽取旧版内容。分类上下文包含固定版候选，比较已有候选可解释。“这个结论”只是子串时不触发快捷解释；另一个对象、届次、地区或新目标需新案。同对象字面重叠不是扩大目标的许可。

`services.budget` 是 interaction 池，`remainingBudget` 是研究window，两者分开。分类后同案补查还检查研究的 search/read/model 及 token、时间、金额余量，不刷新预算。路由不调用 search/read/checkpoint；供应商失败/输出错误或 Abort 不重试。P 保留固定版本/stale、epoch、幂等键、队列及累计2次/2000输出的外层门。

实际补查仍走普通 run，按新追问逐目标覆盖。明确 followup 的新run可对已捕获 URL 有界刷新一次，保留旧与新 capture；同run不重复读，失败即止。测试实跑旧截止→缺延期公告→合法新query→同URL新正文→复核新截止，原checkpoint不改写。

## Watch 比较

`compareWatchResult(WatchComparisonInput, InvestigationServices, AbortSignal): Promise<WatchDecision>` 只比较固定 before 与 candidate。

- 范围/目标不同、读取失败、引用不全、额度不足或比较失败返回 unknown，不宣布无变化。
- 事实签名保留数字小数点、正负号、标点、单位大小写与词界；不含UUID、抓取时间和run。全案条件/未知与逐命题条件也参与事实视图，不用全文hash代替语义判断。
- 极窄无模型快路径需要同事实、同关联摘录/限制，并重走直接可抽取字段的目标→命题→证据门；新抽出的条件必须已保存在candidate。单目标并不豁免覆盖核验。
- 其他比较至多1次 `purpose=watch_compare`，`investigation.compare.v1`，输出<=1400，输入<=min(24000,剩余额度)。unchanged必须equivalent=true、每个goal都有合法完整覆盖、没有核心未知。
- 身份候选不需要被伪造为事实claim。私有比较输出可给candidateIndexes；候选仅覆盖身份目标，conclusion/gap_resolved须显式goalIndexes并指向唯一已消歧候选，不能拿名称证明免费或从两个同等候选中强选一个。候选重要冲突须有已核对的确定线索冲突。
- significant 的每条change引用candidate内合法、有关系的claim/candidate及完整可用证据；纯身份变化可 `claimIds=[]`、非空evidenceIds。P/M现有公共ChangeSchema/WatchStore允许这种表示；未新增公共字段。界面及通知仍由P/M处理。
