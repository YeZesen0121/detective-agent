## 先看分工

| 人 | 人需要做什么 | 其 Agent 做什么 |
| --- | --- | --- |
| 你 | 开通账号/授权、转交阻塞、判断调查案例与使用体验、单独讨论 UI | 主 Agent 做共享底座、平台、盯梢、集成和技术复核；用户侧另安排唯一前端实现 Agent |

旧文件名里的 A/B/C/D 是模块代号：队友 A 对应旧 A；队友 B 对应旧 C；旧 B 是前端，留在你这边；旧 D 是主 Agent。不要把旧 B 文件发给队友 B 作为其工作任务。

## 第一阶段：让主 Agent 发布共同底座 G0

G0 就是所有人共用的项目骨架、数据格式、模块接口和测试命令。它由主 Agent 负责，队友不各自创建一套。

你负责：

- [ ] 配合 GitHub 登录和协作者授权。若远端暂时未开通，让主 Agent 先做本地底座；发布给队友前补齐统一仓库。
- [ ] 根据主 Agent 的具体操作单开通元宝、运行时模型、正文读取和 TTS 所需服务。开发 Codex 的额度与产品运行 API 分开核对；不能假定 Toklens 活动 Key 覆盖元宝或语音。
- [ ] 对需要购买的服务器/套餐，只看主 Agent 给出的用途、价格、到期和替代方案后决定；初始 300 元不视为自动购买任意服务的权限。
- [ ] 拿到主 Agent 填好的[派发记录](11-派发记录与阻塞模板.md)：仓库 URL、基准提交、契约版本、分支、启动/测试命令和当前可用接口。
- [ ] 将派发记录发给两位队友。他们必须从同一个基准提交起步。

主 Agent 负责：

- [ ] 按[总计划 G0](00-并行开发总计划.md)建立统一工程，锁定经过兼容性验证的依赖；所有共享类型、接口、根依赖和迁移由它维护。
- [ ] 建立 `src/shared/contracts.ts`、`src/shared/ports.ts`、五类受控夹具和 `docs/接口契约.md`。明确调用签名、HTTP 路径、错误格式、枚举、版本、预算和取消传播。
- [ ] 固定截图服务所需的模型/视觉接口、伴读补查意图和音频返回形式，给队友 B 提供测试替身；不能让 B 等 A 全部写完才开始。
- [ ] 建立并验证 `npm run dev`、`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`。按目录运行测试的参数以实际脚本为准。
- [ ] 共享夹具通过 schema 校验，空骨架可以启动、检查和构建。模块开发可使用明确标注的测试替身；平台尚未完成的能力逐项列出，不冒充运行能力。
- [ ] 提交底座并记录真实 SHA。未经校验的文档或只有目录名的工程不算 G0 完成。

**该阶段完成标准：** 两位队友可以在各自机器按同一套命令取得、启动和验证工程，并读取相同接口。不是等所有功能做完才发底座。

## 第二阶段：你看首条真实调查，Agent 处理联调

- [ ] 主 Agent 合并队友 A 第一份小 PR，连接真实元宝、正文读取与证据结果；尚无正式 UI 时先用 API 记录验证引擎，不能据此宣称完整用户体验通过。
- [ ] 主 Agent 维护会话权限、预算账本、任务状态、幂等、事件和不可变结果；与模块分批集成，不等队友全做完。
- [ ] 主 Agent 尽早部署健康检查和持久存储，验证目标环境能访问供应商；数据库迁移、部署和后端工作不等待视觉定稿。
- [ ] 你看一张“案例卡”：问题、答案、关键证据原文及链接、仍未知的部分、为什么补查/停止。只需要指出不可信或没帮助之处，不替 Agent 阅读所有日志。
- [ ] 你提出的问题由主 Agent 转成失败案例/验收项，队友修复后重新展示同一案例，不仅口头说已改。

首批案例沿用 T01、L01、F01；涉及“当前”的事实在实际测试时刷新来源。除演示候选外，加入原文不可读、转载、矛盾线索和无证据等反例。

## 第三阶段：UI 独立推进，服务并行接入

- [ ] 在独立 UI 会话确认代表性案件的输入、调查中、结果/证据、伴读、错误/未知、历史更新状态；不要只确认漂亮首页。
- [ ] 让 UI AI 输出可交付的设计说明、状态清单、示例内容和关键移动端处理。若它只产设计，你再把设计交给用户侧前端实现 Agent；不默认它也负责代码。
- [ ] 指定唯一前端写入者，遵守 `src/web/`、`tests/ui/` 的边界。若更换执行 Agent，先交接已提交代码，不让两个 Agent 同时重做前端。
- [ ] UI 所需字段若缺失，先向主 Agent 提接口变更，由主 Agent 更新契约并通知两位队友；不在 UI 里创建另一套后台数据结构。
- [ ] 主 Agent 接入队友 B 的截图、伴读和 TTS；用户侧前端实现 Agent负责按钮、页面、播放器和打断交互。
- [ ] 主 Agent 实现盯梢：后台检查、变化复核、通知、历史版本；完成关闭浏览器后的真实执行记录。

**你看的东西：** 页面能否看懂、关键来源能否打开、未知是否突出、伴读能否方便打断。声音和手机操作需要实际试一次，自动测试不能代替听感与真实设备。

- [ ] 主 Agent 检查每个 PR 的需求覆盖、测试结果、真实/模拟标识和未完成项；不能凭“Agent 说完成了”合并。

- [ ] 录三条真实调查与盯梢闭环。回放、合成测试页和加速检查均明确标注，不制造假通知或假搜索。

## 白天和睡前怎么管理

白天按“有关键结果或阻塞再找你”运行，不要求你固定每半小时看一次。

- [ ] 每次查看只问主 Agent：现在已验证什么？还有什么阻塞？下一项需要我做什么？
- [ ] 睡前让各 Agent 保存分支、当前提交、测试结果、下一步和待你处理的问题。
- [ ] 夜间只做已经明确范围内的工作；没有充分依据的产品取舍、追加费用、公开发布等待你回来。依赖阻塞的任务停在该处，能独立做的继续。
- [ ] 确认本地机器和网络满足持续运行；休眠/关机不能保证目标继续。开发 Agent 运行与产品盯梢服务器运行是两回事。
- [ ] 目标按阶段设置，不写“永远优化”。Token 限额与平台金额限额分开；具体预算未设好时，不开启无人看管的付费循环。

## 复制给主 Agent 的启动提示词

在项目目录打开开发会话，将下面整段作为首条消息。它供你主动开始下一阶段使用，本文件生成不等于已经执行。

```text
你是侦探 Agent 项目的主集成 Agent。请先读取 docs/协作交接/07-你的详细待办.md、00-并行开发总计划.md、04-D-总集成与盯梢.md、06-测试与验收方案.md、10-UI独立协作边界.md、11-派发记录与阻塞模板.md，以及完整 docs/AI开发需求文档.md v1.0。已有需求不要重新访谈。

这次我启动开发。先检查当前目录、Git状态、已有改动和文件真源，保留他人工作。第一个目标是完成 G0 并发布可供两个队友共同起步的契约和工程基线；不是一口气完成整站。按总计划建立真实 schemas/ports、带类型的模块测试替身、接口文档、测试夹具与启动/验证脚本。测试替身不能进入真实生产链路。费用上限、重试、取消、会话归属和历史快照必须有明确契约。

队友 A 负责调查引擎与 search/model/reader 适配；队友 B 负责附件提取、伴读和TTS。你拥有共享底座、平台、盯梢、路由组装、根依赖、迁移、CI与集成。UI由我另开会话讨论；你不要设计正式页面或修改 src/web/、tests/ui/、DESIGN.md。你可建立已约定的前端构建配置和不含产品设计的启动占位，随后将前端代码所有权交给唯一前端实现 Agent。

沿用技术栈候选并核对兼容版本，按现有参考文档和固定源码快照做有依据的实现，不从头寻找一堆新框架。设计决策记录 PRD/AC、研究方向、参考机制、commit/文件位置、采用理由和舍弃部分。来源没证明的结论标未知。

可以先本地创建工程；远端仓库或服务需要登录/选择/付款时给我最短操作单，不索取明文密钥、不自动购买。不要擅自创建多个产品仓库。用户侧提供账号后填写真实派发信息；仓库地址与提交不存在时不得编造。

G0完成前运行实际验证，报告命令、退出码、通过/失败/跳过项、当前提交和未就绪平台能力。发布 docs/协作交接/11-派发记录与阻塞模板.md 中的公共基线信息，让队友从相同SHA开始。G0完毕交付阶段成果；后续平台、盯梢和联调按下一阶段目标继续，不能将G0完成说成产品完成。

遇到无法自行解决的阻塞，按交接模板写出脱敏原始错误、复现方式、已尝试方法和需要的具体协助；保存工作并推进不依赖它的任务。不得靠无限重试耗费额度。不要未经授权给其他聊天或人员发消息；把可转交文本交给我。
```

之后可分别设置三个阶段目标：G0共同底座；平台/真实调查集成；盯梢/总验收。采用目标模式时必须同时给出验收条件和运行预算；目标不会自动管理两位队友电脑。

## 给你的完成判断

你不需要理解所有技术细节，但应能拿到：统一仓库、可访问网站、真实调查案例、关键来源、后台盯梢记录、测试汇总、剩余问题与费用。只有一段“已经全部完成”的回复，不是交付。
