## A1：适配器与首条真实调查

**进入条件：** 已同步G0基线，实际类型/port/测试脚本可读取；真实联调另需相应服务凭证与有限预算。

- [ ] 为SearchPro解析和错误分类写失败测试：Pages逐条解析，坏条目不吞掉好条目；鉴权/限流/超时/空结果/业务Error区分。
- [ ] 实现元宝adapter、模型adapter和reader adapter。所有外部调用经过统一预算和取消入口；不在日志打印密钥。
- [ ] reader记录原文已读、仅摘要或读取失败，保留来源和时间。动态摘要不能当全文。
- [ ] 实现G0的 `runInvestigation`，走范围→查询→搜索→读取→证据→结果草案；最终持久化/归属/版本提交由主 Agent平台完成。
- [ ] 至少一条实际元宝查询保存脱敏请求记录、来源、结果和费用；没有真实凭证时做受控测试并标受阻，不能声称实搜通过。
- [ ] 提交第一份小PR，让主 Agent尽早联调。不要等三种模式全写完。

**通过标准：** 有来源支撑的结果草案能通过共享schema；坏响应和失败有正确出口；测试记录区分真实与模拟。

## A2：四项能力与三基本模式

- [ ] 查询规划记录目的与命题，不固定凑次数；关键对象缺失时提出必要追问。
- [ ] 建立来源、命题、证据及支持/反驳/背景关系；识别转载，保留未知，不把相关性分数当可信度。
- [ ] 检查来源冲突的对象/时间/地域/版本/适用条件；证据不足时给已知、缺口和下一步。
- [ ] 缺口驱动第二轮调查，保留新增证据及外部可见操作记录；不输出虚构进度或隐藏思维过程。
- [ ] 查真假保留命题条件；查最新对齐发布时间/事件时间/查询时间及生效条件；查模糊保留有来源候选与区分线索。
- [ ] 取消后不排队新调用；普通初始12次搜索包含重试，达到上限后无第13次；约7分钟有效运行预算不含等待用户时间。其他次数/token/读取额度依G0配置。
- [ ] 模型输出修复与重试也有限额，技术失败不被写成事实为假。
- [ ] 同一调查质量配置不受简答/证据链/伴读呈现选择影响。

**通过标准：** 对应AC01–04/07/08的关键样例逐项有证据；质量评审针对事实支持，不只判断JSON格式正确。不要移植Jina强制作答路径或Vane速度档逻辑。

## A3：追问与跨模块复用

- [ ] 按G0实现 `answerFollowup`：旧证据解释、同案补查需求、建议另案；只有确需新材料时补查。
- [ ] 追问和澄清不刷新原预算；显式继续追加额度由平台处理。
- [ ] 同案补查草案带清晰来源和新增证据，主Agent提交新结果版本；不覆盖旧结果。
- [ ] 伴读追问通过相同入口；盯梢通过相同调查引擎运行，不依赖浏览器连接。
- [ ] 与主 Agent联调“缺信息→回答→继续”“预算耗尽”“旧报告→新版本”；输出依赖缺口，不私改共享协议。
