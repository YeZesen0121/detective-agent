## 所有权与接口

拥有 `src/web/`、`tests/ui/`，以及批准后的 `DESIGN.md`。不碰后端、migration与共享契约。从 G0 实际 contracts 推导界面类型，通过单一 `src/web/api/` 调用已定义 HTTP；禁止在页面里制造另一套 ResultVersion。

G0前可在独立UI会话整理屏幕状态与同一案件的比较草图；G0及设计交接就绪后，唯一前端实现Agent先用共享夹具实现。夹具标明合成，仅用于开发/测试，不能进入正式真实调查路径。真实接口接通后在实际运行状态中验收。

## 小 PR 顺序

- [ ] 功能外壳：体验码、基本模式/通用模式选择、提问、截图入口；暖白/深色文字/适量强调色的既有起点，集中 theme 变量。
- [ ] 输入→澄清→调查中→结果：操作记录只来自服务端事件；取消/重连/到限/部分失败均有状态；来源可展开，空状态不显示假结论。
- [ ] 结果与证据：简答保留限定、未知和来源；证据卡从结论深入到claim/evidence/source；三模式任务开始时选定，不新增任务内随意切换。
- [ ] 伴读 UI：3–5短段、打断/返回位置、直接收尾、证据入口、朗读停止/换段。人物表达不把不足证据变确定。
- [ ] 历史与盯梢 UI：创建/暂停/删除/续开/限频立即检查，站内通知；旧版明显提示更新，新版显示差异和返回旧版。
- [ ] 同一真实案例精修与手机核对：长中文、长标题、多来源、无结果、错误、三图、键盘/触控、较小屏幕；不以桌面截图代替移动端操作。

## 测试与验收

`tests/ui/` 使用 Playwright，至少覆盖：重复点击提交不创建多个run；刷新查询已有状态；部分结果/未知可读；来源点击定位正确；复制包含结论/条件/时间/链接；旧报告与伴读不混新版；通知进入新报告；切段不叠音；小屏幕核心按钮可操作。

统一命令在G0建立：typecheck/test/build，以及 `npm run test:e2e -- tests/ui`。负责 AC05/10/13/14/15 的 UI 部分，参与 AC06–09/11/12。视觉检查和运行测试分别报告。

## 与用户讨论的范围

首屏信息次序、结果排版、证据展开方式、伴读节奏与整体侦探气质可以继续讨论。真实搜索、未知出口、模式定义、历史快照、质量一致和已确认功能范围不重新投票。每轮用相同案件与内容对比方案，避免用空白占位稿判断信息设计。

交付 PR 附桌面/手机截图、交互测试、真实/夹具标识、依赖接口与未完成状态。角色自定义、关系图与重动效不抢占核心路径。
