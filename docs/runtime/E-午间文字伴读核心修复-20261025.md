## 实际问题与改变

旧 build 每段按模型引用重复调用完整 facts，第一段再拼整个 overview，末段再拼下一步。同一组条件、理由和摘要会重复三至五遍；证据 limitations 的内部 proof JSON 直接进入文字。

新 `narrative.ts` 从可信固定报告编排结论、依据、边界/未知、下一步。三段提案把边界和下一步合并；四/五段提案采用四个阶段。必要条目只在完整条目边界换段，每段最多 900 UTF-16 单位，总计三至五段；不依赖模型自由正文补事实。所有原命题状态、条件、缺口、冲突、未知、证据实质限制和核查时间整体保留。摘要仍由原报告完整投影，用于保存和收尾。

去重仅对相同完整条目进行（允许末尾句号差异），不能用子串包含判断替代语义核对。因此摘要内嵌的条件可能在边界段再次出现一次；这是保留独立限制的保守选择，已消除逐段重复整份 facts/overview 的主要问题。不能声称这是经过真实模型验证的语义摘要。

`presentation.ts` 仅做展示投影：移除四类明确的程序状态/proof marker；年份显示为“材料标注年份…不代表当前仍有效”；带 capture/excerpt 前缀的限制保留冒号后的全部实质文字，不删否定、真实性或范围限制。原保存结果不变。打断回答的 facts 也使用此投影。

合法 `EvidenceLink.quote` 需确实位于对应 verbatim excerpt，且扩展为完整原句后不超过 600 字，才作为引文显示。仅有子串匹配不能防止从“不同意延期”截出“同意延期”，故保留整句上下文；过长或非法引用退回原证据卡提示，短材料可展示完整 excerpt。snippet 单独标为“摘要线索（未核实正文，不能作为确证）”。不生成新证据/assetId。

引用使用现有有限闭包，覆盖固定报告的全部命题、结论块和冲突；每段绑定该闭包，避免无依据段落。无命题报告允许展示其保存的非 raw_capture_only 线索；证据为空则明确没有可展示引文，不补出原调查答案。未改 cursor/finish/音色/音频授权/版本写入路径；旧会话不重新生成或回写。
