## E3：可测试 TTS 核心，明确持久化接缝

现有 ExperienceServices 有 tts，但没有音频存储/单飞端口。不能伪造 assetId，也不能为了通过接口偷偷写全局内存任务。
在 companion/audio-ports.ts 定义供 P 注入的模块私有 AudioStorePort：
    type AudioLease = { jobId: string; epoch: number };
    type SpeechClaim =
      | { kind: 'observe'; manifest: AudioManifest }
      | { kind: 'produce'; manifest: AudioManifest; lease: AudioLease; missingIndexes: number[] };
    interface AudioStorePort {
      claim(input: SpeechInput, cacheKey: string, chunks: readonly string[]): Promise<SpeechClaim>;
      putChunk(lease: AudioLease, index: number, bytes: Uint8Array): Promise<string>;
      finish(lease: AudioLease, status: 'ready' | 'partial' | 'failed' | 'cancelled',
        safeError: string | null): Promise<AudioManifest>;
    }
由 P 适配持久存储/鉴权；E 的模块工厂接收此端口。claim 短事务保证同key只有一个produce；其他请求返回observe（已完成缓存或正在生成），E立即返回其manifest不调用TTS。缺块只能由produce.missingIndexes指定；putChunk验证epoch并幂等写入/返回assetId；finish失效lease必须拒绝，不能恢复已取消任务。P 实接前 synthesizeSegment 不挂生产路由。
缓存 key 必须包括保存版本、正文hash、provider/voice/speed/codec、切段版本。P在服务恢复时结合usage ledger处理未知调用，不自动抢占超时任务并重发；对账或明确的新有预算尝试才重授生成权。E使用严格double验证produce/observe及过期拒绝，不能声称已经证明跨进程单飞。
