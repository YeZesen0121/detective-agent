## 按小 PR 顺序

- [ ] API 适配与脱敏探针：SearchPro Pages逐条解析；坏条目隔离；业务 Error、鉴权、限流、超时、空结果区分；正文状态如实保存。没密钥只能报告 fixture 测试通过。
- [ ] 首条端到端调查：范围→查询→搜索→必要原文→证据→结果。先连通一条，再丰富规则；不可把简单路径当四项能力已经全部完成。
- [ ] 查询与证据循环：记录查询目的/命题，去重与转载关系；缺口驱动后续查询；模型建议动作，程序约束范围/预算/取消。
- [ ] 三基本模式：真假保留条件，最新区分四类时间，模糊保留多个有依据候选及区分线索；混合问题能复用规则。
- [ ] 停止、澄清、继续、追问：不填默认城市/年份；不把等待时间计入运行预算；原轮预算不因追问刷新；补查形成新结果版本。
- [ ] 引用与裁决检查：id存在、摘录来源、支持关系分别验证；无证据出口仍给已知、缺口、下一步；技术失败不是事实为假。

## 关键测试

在 `tests/investigation/` 按模块建立测试，先写失败样例再实现；至少验证：
- 同源三转载不算三个独立依据；旧公告与新公告先对齐届次/生效时间。
- 全部检索失败时停止无效递归；仅摘要不能标全文。
- 第12次搜索含重试后无第13次；取消后无新调用；模型结构修正也有上限。
- 无法确定时输出 insufficient 与有用下一步，不因 definitive 风格强制作答。
- 失效引用id不能通过发布校验；相关背景不能冒充支持。
- basicMode规则不同，但presentationMode不影响相同调查输入的质量配置。
- 追问解释不搜索，补查不重置账本，新增预算只能来自显式继续。

使用统一 `npm run typecheck`、`npm test -- tests/investigation`、`npm run build`（G0建立）；最终对应 AC01–04、AC07–09，并协助 AC05/06/11/15。

## 交付与禁止项

每个 PR 附所用参考机制、修改/舍弃原因、测试结果、未验证限制；真实探针只保存脱敏 requestId、时间、字段与费用。禁止依赖模型既有知识伪装元宝；不复制 Jina 强制作答与心理揣测，不为了凑批次制造搜索，不另起大型多 Agent 框架。不要把不同模式各做成互不兼容的聊天提示词。
