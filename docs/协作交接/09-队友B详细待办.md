## B1：截图服务

进入条件：G0的附件、权限、模型/视觉port、预算与测试替身已发布。真实视觉adapter未完成时可先受控开发，真实验收随后补。

- [ ] 先写附件验证与逐图提取测试：非法格式/解码失败、尺寸限制、顺序与归属、关键文字不确定、多图部分失败。
- [ ] 按G0实现 `extractAttachments`。输入有稳定attachmentId；逐图输出提取内容和关键歧义，不直接判真假。
- [ ] 保留原文与提取内容的对应；看不清日期、否定词、说话人时标未知，不猜出一个“更容易搜”的版本。
- [ ] 三张里一张失败不丢其他两张；遵守实际配置的大小/请求上限。默认最多3张，不自行降为1张；如触发PRD条件减法，报告原因由主Agent统筹。
- [ ] 用户补充确认后交回同一调查引擎，不能在截图模块私自搜索。
- [ ] 对本会话外的附件访问拒绝；存储/授权能力由平台提供，缺失则先报告，不写绕过逻辑。
- [ ] 接入真实视觉服务，人工核对至少日期、否定词、说话人和多图归属；记录脱敏调用和费用。

**交付：** 一个可审查PR、受控测试、实际识别结果及仍辨认不清的地方。没有真实视觉结果时明确“待联调”，不能标AC06完成。

## B2：绑定版本的文字伴读

- [ ] 按G0实现 `buildCompanion`，只消费指定不可变ResultVersion，生成3–5短段与合法证据引用。
- [ ] 不把普通解释写成新事实；不能删除“截至”“可能”“证据不足”等改变判断的限定。
- [ ] 按G0实现 `replyCompanion`，处理打断、游标保存、返回主线和直接收尾；不设答题门槛。
- [ ] 新事实追问返回统一补查意图，由调查引擎/平台处理，不再造搜索循环或刷新预算。
- [ ] 新结果出现时旧版伴读仍绑定旧版事实，更新提示由版本关联提供；不把新旧资料拼接成同一段。
- [ ] 同一证据包比较普通结果与伴读：结论、限制、冲突和关键来源一致。

**交付：** 服务PR、同版本一致性/打断游标/更新隔离测试与一份可读示例。示例明确标注真实或合成，不做正式UI。

## B3：TTS服务

- [ ] 按G0实现 `synthesizeSegment`；校验预置音色，按实际接口限制切段，保留完整语义和限定。
- [ ] 相同正文/音色/语速复用缓存；不同参数不可串音。音频标识与访问由平台进行会话控制。
- [ ] 所有合成走统一费用入口；取消不再排新请求，已发送请求可能仍完成/计费，如实记录。
- [ ] 错误时保留文字与可重试状态；不要用静音文件冒充合成成功。
- [ ] 实际生成一段含“不确定/截至日期”的中文音频，由人听一次并记录结果。选定活动Key不能调用TTS时报告，不能把GPT额度当通用语音额度。
- [ ] 给用户侧前端实现Agent明确音频接口、状态和停止语义；播放、切段不叠音由前端实现，B参与联调但不修改前端文件。

**交付：** TTS服务PR、缓存/失败/费用/访问测试、真实音频验证。服务单测不等于手机实际播放通过。
