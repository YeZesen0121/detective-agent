后续P接入增量已实现Run/澄清/事件/结果/复制的存储与HTTP，实际签名和配置边界见[平台接续记录](../../runtime/P-平台接续.md)、src/shared/runtime-http.ts。下表保留G0派发时的历史状态；不能据它否定后续实现，也不能把受控宿主当真实调查已组装。I/E/W/M原G0基准保持不变，新接口按P发布增量取入。

不要通过“所有返回都200+空数组”掩盖未实现能力。测试替身只在测试中，生产入口未配置服务则显式不可用。生成UI不需要先改后端数据库表。

## 五条接入规则

1. 组件只接收数据、状态、动作；如提交、停止、查看来源、打开新版、打断、继续、停播。复杂请求与版本逻辑放W控制器，颜色布局留U。
2. URL携带实体ID即可定位；取结果按versionId，不把latest当固定报告。前端不能发送sessionId/额度池/供应商Key。
3. 等待反馈与事实状态分开：网络reconnecting不等于任务failed；cancelPending不等于cancelled；读取失败不等于事实为假。
4. 稳定ID贯穿输入图、run、query/source/evidence/claim、resultVersion、companion、audio、watch/notification。类型复用shared，HTTP精确schema缺口由P补，私有adapter不得冒充全局契约。
5. 不引入前端数据库镜像；controller可用内存渲染状态，持久事实以服务器为准。刷新恢复已有run，不重复POST收费任务。

## 状态接入验收

|场景|必须预留的数据/行为|验收责任|
|---|---|---|
|开始任务/重复点击|固定幂等key、返回已有run、禁重复提交反馈|P原子性＋W状态|
|澄清/不知道|prompt/options/proceedWithUnknown，不虚构scope|I判定＋P存储＋W呈现|
|断线/刷新|持久run、afterSeq、重新查询，不假停止|P＋W|
|取消/到限|停止新付费调用、保留部分证据和stopReason|P预算/epoch＋I退出＋W状态|
|条件/冲突/摘要来源|claim状态、限定、readStatus、证据链接可追溯|I事实＋W投影＋U信息层级|
|旧报告有更新|原payload不变，updateNotice独立，新旧可导航|P快照＋W固定选中版本|
|伴读打断/继续|绑定旧version、保存cursor、research_request交I|E＋P＋W|
|停播/换段|本地立即stop，epoch拦迟到，不承诺零云费用|W播放＋E切段＋P费用|
|盯梢失败/暂停/过期|unknown与unchanged不同，失效lease不通知|M＋I＋P|
|身份/服务过期|401保留安全输入，历史不能跨浏览器获取|P＋W|

## 接口变更如何协调

P发布实际schema/HTTP小提交，附输入输出/错误/版本/受影响角色；W把新字段映射进adapter，M/E不改shared。契约差异不得靠as unknown或静默丢字段消化。
尤其要预留但未实现：E音频生成权/存储端口、M事务租约端口、P请求/响应schema。前两项使用各任务书中私有接缝做受控模块，真实接入由P发布并验证。

设计定稿后，W在同一套controller上实现页面；先最短文字路径真实联调，再截图/伴读/盯梢，最后真实手机/音频/关闭浏览器等完整旅程。后端全完成不是开始UI设计的条件。

## 依据与取舍

PRD、实施设计D04/D06/D08/D10和固定源码为主；本轮ui-ux-pro-max查询 loading cancellation feedback 的Feedback/Loading Indicators匹配“异步操作须给可理解状态”。采纳状态可观察性，不提前选择视觉样式，也不以UX规则证明后台正确。工程取舍为已有TypeScript+注入端口+Vitest，避免为了等UI引入额外状态框架或新后端。
