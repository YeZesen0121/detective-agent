# 侦探 Agent · 调查工作台原型 v2

用 `design-taste-frontend`（Taste Skill 2.1.4）重做的一版布局原型。仍然是**单文件、零依赖、纯前端**：所有案件、证据、来源、时间都是示例数据，没有后端、没有真实检索、没有上传与语音。

- 主文件：`index.html`（76 KB，内联 CSS/JS）
- 设计方向：`framed-sheet`（发牌 seed `882871166`），保留品牌色与宋体标题（`--keep palette,type`）
- 屏幕要回答的问题：**这一桩到底成不成立、凭什么、哪里还不知道**

## 打开

```bash
# 直接打开
start "" docs\ui\prototype\index.html

# 或起本地服务（复制按钮在 file:// 下可能被浏览器拒绝）
cd docs/ui/prototype
python -m http.server 8123
# http://127.0.0.1:8123/index.html
```

URL 参数可直接进入某个状态，便于评审和截图：

| 参数 | 值 | 说明 |
|---|---|---|
| `view` | `idle` / `clarify` / `running` / `result` | 默认 `idle` |
| `case` | `mixed` / `supported` / `refuted` / `insufficient` / `mixed-v2` | 结论态；`mixed-v2` 是更新后的新报告 |
| `theme` | `dark` | 暗房 |
| `updated` | `1` | 显示「已有更新」横幅 |
| `companion` | `1` | 自动打开伴读浮层 |
| `freeze` | `1` | 调查中冻结在 5 步，便于截图 |

右上角「演示」可切换场景、结论态和更新提示；正式版不会出现这块。

## 布局改了什么

### 1. 从「三栏并排」改成「L 形框 + 一张纸 + 一条台账」

旧版三栏同色同高，像后台；新版把左侧案卷柜与顶栏合成一个暖色 L 形框，工作区是一张有 1px 边、16px 圆角、**没有阴影**的纸，台账作为纸内右侧的窄栏。层次只靠一个色调台阶，不靠卡片阴影。

框退后，纸和结论上前。`sheet` 的网格：`minmax(0,1fr) clamp(300px,23vw,360px)`，左栏 232px；1440 下纸约 1200px，正文与台账共用一条上边缘。

### 2. 结论页压进一屏（1440×900）

结论、命题、4 条证据、未知区、操作按钮全部在首屏内。做法不是删内容，而是：

- 证据默认只显示「关系 + 来源 + 一句结论性说明 + 读取程度」，**摘录折叠**；
- 唯一的关键冲突（S4「收书 25 日 18:00」）默认展开摘录；
- 「展开其余证据」一次展开/收起全部摘录。

这样既保留「结论→命题→证据→来源」的分层，又不把结果页做成论文附录。

### 3. 证据语义补齐到 4 种关系

旧版只有「↑支持 / ↓限定 / ·背景」，缺 `contradicts`。新版四种都有：

| 关系 | 标记 | 用色 |
|---|---|---|
| 支持 | 实心方点 + 支持 | 绿 `#247b50` |
| 反驳 | 实心方点 + 反驳 | 红 `#a3231d` |
| 限定 | 实心方点 + 限定 | 琥珀 `#8a5a1f` |
| 背景 | 实心方点 + 背景 | 灰 |

读取程度独立成徽标：`已读全文 / 已读部分 / 仅摘要 / 截图`。**关系是判断，读取程度是证据强度，两者不混。**

### 4. 四种结论态，数据各自成立

| 态 | 印章 | 示例 | 计数（由证据数组算出） |
|---|---|---|---|
| 成立 | 成立（竖排） | 市集搬到一楼中庭 | 支持 3 · 背景 1 |
| 部分成立 | 部分成立（2×2） | 延期到 26 日，但收书 25 日停 | 支持 2 · 限定 1 · 背景 1 |
| 不成立 | 不成立（竖排） | 26 日还能交书 | 反驳 2 · 背景 2 |
| 证据不足 | 证据不足（2×2） | 26 日会不会延长到晚上 | 限定 1 · 背景 2 · 未知 2 |

计数不是写死的：`count()` 从 `evidence[]` 的 `rel` 累加。演示切换时整份案件（问题、命题、结论、证据、未知、伴读）一起换，不会出现「反驳态配支持证据」的拼接。

### 5. 移动端顺序修好

旧版 <820px 时案卷柜先堆叠，首屏 1200px 都是历史列表。新版：

- 舞台优先，案卷柜变左侧抽屉（「案卷」按钮），台账变底部 sheet（「台账」按钮）；
- 三种「查什么」在 620px 以下压成三列小卡，描述隐藏，**「开查」回到首屏**；
- 触控目标 ≥36px（移动端按钮 36px、主按钮 40px）；
- 390px 下无横向滚动（实测 `scrollWidth - innerWidth = 0`）。

### 6. 调查中：阶段脊柱，不是假进度

用「拆题 → 检索 → 读原文 → 核对」四段标出真实阶段，配当前动作一句话、已翻到的材料、按缺口排的下一步。没有任何百分比进度条；右栏的 12 格是**调用预算**，与中间「已用 2 / 12」同步，不是完成度。

### 7. 「继续调查」真的续跑

旧版点「继续」从第 1 步重跑。新版保存 `idx`，停止只暂停计时与调度；继续从当前步接着走。交互测试：停在第 4 条事件，继续后到第 7 条，没有回到 1。

### 8. 版本更新：旧报告不改写

横幅只出现在旧报告上方：「这份报告已有更新 · 10-25 09:12 复核」。点「看新报告」进入同一案件的 `mixed-v2`：多一条 S5（雨天改址），计数从 2 变 3，正文顶部显示「相对旧版」的变化；点左栏 №007 回到旧版，正文、引用、计数仍是 2。旧报告没有被覆盖。

### 9. 伴读、追问、盯梢各有位置

- 伴读是右侧浮层（360px），**不挡结论与证据**，带段进度、下一段、收尾、听、关闭；
- 「接着问」展开一个输入行，明说「只解释已有证据，不重搜」；
- 盯梢是台账底部的一个动作，开启后变成「已盯梢 · 下次 22:40」，不弹假通知。

### 10. 字段对齐契约

- 输入上限改为 **4000 字**（`实施接口契约.md:51` 的 `originalQuestion` 上限），不是旧原型的 500；
- 案件状态用 `idle / clarify / running / result` 四个视图对应 `draft / clarifying / running / completed|partial`，不再用三个 `<section>` 硬切；
- 台账事件是 `ProgressEvent` 的展示层：时间、动作、是否检索；没有模型自由发挥的「思考过程」。

## 验证

用 Taste Skill 自带检查器（`inspect.mjs` 自动切 app 规则）跑过：

| 状态 | 宽度 | 结果 |
|---|---|---|
| 待受理 | 1440 / 390 | 0 FAIL，1 WARN（tiny-text） |
| 待澄清 | 1440 / 390 | 0 FAIL，2 WARN（hero-void、tiny-text） |
| 调查中 | 1440 / 390 | 0 FAIL，1 WARN（tiny-text） |
| 结论·部分成立 | 1440 / 768 / 390 | 0 FAIL，1 WARN（tiny-text） |
| 结论·成立 / 不成立 / 证据不足 | 1440 / 390 | 各 0 FAIL，1 WARN（tiny-text） |
| 暗房 | 1440 | 0 FAIL |
| 伴读浮层 | 1440 | 0 FAIL |
| 已有更新 / 新报告 | 1440 / 390 | 各 0 FAIL |

截图与 `report.json` 在 `checks/<状态>/`。

**保留的 WARN 及理由：**

- `tiny-text`（约 47–60% 文本 <13px）：这是证据台账，时间、来源编号、读取徽标、台账元数据按 app 规则允许的 11–12px 处理；正文与证据说明保持 13–14px。不是把正文缩小来塞内容。
- `hero-void`（待澄清 33%）：待澄清刻意只留一个问题，空白是让用户只回答这一件事；没有用假说明填空。
- `palette-cream`：需求文档 §1 明确「暖白 / 深色文字 / 适量强调色」。这是对 Taste Skill 默认调色板的**有意偏离**，用 `--allow palette-cream` 放行，不是漏检。

## 真实与模拟边界

**真的：** 视图切换、模式单选、字数统计、开查后的 8 步本地模拟、停止/续跑、结论四态切换、证据展开、复制到剪贴板（http 下）、伴读开关与分段、暗房切换、移动端抽屉/底部台账、更新横幅与新报告切换。

**假的（示例数据）：** 四个案件的全部内容、来源、时间、费用、事件、伴读文字。没有 `fetch`、没有 localStorage、没有真实检索。

**没接的：** 截图上传、正文抓取、TTS、追问路由、盯梢调度、体验码校验。点击时只给明确的原型提示，不假装成功。

## 已知限制

- Windows 上没有 Songti SC / PingFang SC，标题回退到 SimSun，字重与截图不同；macOS 上才是设计稿的样子。
- 未在 Safari / Firefox / 真机测试；`color-mix()` 需要 Chrome 111+、Safari 16.2+、Firefox 113+。
- 暗房只做了颜色变量，不持久化，刷新回浅色。
- 结论页在 1440×900 内刚好放下；加更新横幅或新版本后会超一屏，需要滚动。
- 所有示例案情为虚构，避开时政与个人私事；不能拿它当真实调查结果演示。
