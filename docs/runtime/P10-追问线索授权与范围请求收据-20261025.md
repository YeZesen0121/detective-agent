## 同案线索更新

pending用户来源只从实际followup_run_inputs＋completed且批准research_same_scope/显式预算确认的job，或真实已回答clarification读取。验证owner/案件/问题及当前执行baseline。PreparationInput.followup的resultVersionId保留**原始已存turn的版本**；后续add_budget可按原规则对齐执行baseline，不能改写用户输入的来源身份。

scope更新只可变knownClues/uncertainClues；对象、原题目标、claimsToCheck、地区、timeScope、基本模式、确认状态及raw referenceTime保持。旧线索不能无痕删除，可保留在uncertain以记录有据纠错。P只做授权/结构门，逐引句语义及确定性由I提议＋独立复核负责，不能称schema证明含义。

迁移010的scope_refinements记录来源、输入hash、前后scope/版本、应用run/时刻；与setScope版本提升处于同一SQLite immediate事务。没有变化也消费该次已处理来源，resume省略已处理followup/clarification，不再付费提取。取消之前未落库不能应用；已应用的是用户线索记录，取消不改写旧报告。真实clarification在取消后可沿resume链继承，不伪造answer。

## scope两阶段请求

scope_model_receipts按逻辑用户输入集合＋schemaId唯一。仅grounded.v1和review.v1，两次输出上限1600/1200；实际消息/prompt内容另核hash，maxOutputTokens改变不能绕过未知阶段。

bindResearchServices的P内部observer在gateway标sent后、原始provider发送前绑定callId；合法返回先作为私有收据保存，再由原gateway计费/epoch检查。128KiB上限，不是可直接展示的scope。旧worker晚返回只可保存真实响应/结算，不可发布；新授权worker相同输入可复用收据，0新增付费。sent/unknown无回包、或进程中断留下pending，默认阻止自动重放；只有本进程可证明尚未发出的失败才记unsent允许下一次明确尝试。改变预算窗/执行baseline不能当新用户输入重开该阶段。

完整初查scope也使用收据，但初查无输入来源不授权随意改已有scope。模型给非法delta仍由I拒绝，不能因有回包就应用。已有回包的未知usage仍保留原gateway预留，不因为缓存读取退款。

scope准备返回澄清而实际model/token/money额度已尽时，P按真实预算停止，已有材料走partial、无材料failed；不让用户进入无法补信息解决的永久等待。旧1model探针仍旧限额，新核心会model_limit，不抬历史预算。

## watch联动

独立审查实际复现：clue patch提升scopeVersion后旧watch仍active但永远不能claim。已记录before/after版本，前台快照事务仅沿连续同范围clue证明链迁移watch版本和baseline、使旧checks/lease失效。缺链显式paused，不能无条件继承换范围；resume拒绝不一致，显式renew也必须可证明同范围。原周期费用/额度不被迁移重置。

同一审查又复现“patch已应用但提交前取消”没有新快照可触发迁移。现在线索版本提升时即原子记录自动暂停来源、暂停旧watch及旧checks；取消后真实显示paused。有证明的新报告提交才可恢复**本机制自动暂停的原active意图**，用户在此期间手动pause/remove会清除自动意图，不能被后续commit擅自恢复。周期到期不自动续期或充值。
