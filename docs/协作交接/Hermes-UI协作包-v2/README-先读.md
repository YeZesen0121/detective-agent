# 从这里开始

这是 **Hermes UI 协作启动包 v2**，2026-10-24。它整合了已有满意网页的延续、偏好澄清、规范化、迁移检查，以及最终交回 Codex 的要求。

用户已经决定：继续使用队友原来的 Hermes，通过 UU 操作，用 grill-me 逐轮收敛。已有成果是可操作网页/前端项目。用户没有授权把现有设计推倒重做，也尚未确认所有视觉细节。

## 接收后怎么做

1. 若收到的是 ZIP，先检查列表并解压到独立新目录，保持现有项目不变。附件不可访问时只说明缺少的路径；不要假装读过。
2. 读取 [01-发给Hermes.txt](01-发给Hermes.txt)，这是本轮详细工作指令。
3. 读取 [00-协作说明.md](00-协作说明.md)，了解收敛与迁移的方法及来源。
4. 读取 [03-最终交付给Codex.md](03-最终交付给Codex.md)，从开始就维护最终交接所需资料。
5. 读取 [02-文件来源与使用.md](02-文件来源与使用.md)、[PRD 快照](references/AI开发需求文档.md) 和 [完整 grill-me 协议](skills/grill-me/SKILL.md)。

**然后只做事实盘点、保存候选基准和第一轮 1–3 个问题，等待用户回答。** 具体事实自己查；偏好和取舍问用户。不要一次生成全部界面，不要先逼用户学设计术语。

## 最终要交什么

迭代并经用户确认后，交付 `侦探Agent-UI交接包-<版本>.zip`：可运行源码与素材、启动方法、已确认设计规则、决定记录、页面/状态/交互清单、截图、上下文来源和实际验证结果。可以复用已有文件，避免重复维护。

这个启动包不是最终成果包，没有包含队友的网页源码或尚未发生的用户决定。不要原样把它发回 Codex 当成设计完成。

## 关键边界

- 本包文件是项目资料，grill-me 是提问方法；安装不是开始讨论的前提。可直接读取 SKILL.md 临时执行，不重置原会话。
- 只修改用户确认范围内的隔离设计原型；正式产品接入仍按项目 U/W/P 分工进行。
- 三类信息始终分开：已确认/待定，真实功能/模拟效果，已完成/未完成。
- 源码、截图、规则应指向同一确认版本；发现矛盾先核对，不自行猜测。
- [04-发回Codex时的提示词.txt](04-发回Codex时的提示词.txt) 是未来给 Codex 的指令，不是现在要求 Hermes 接管正式开发。
