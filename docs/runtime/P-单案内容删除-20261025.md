## 契约与删除边界

认证且符合既有 Origin 检查的 `DELETE /api/v1/investigations/:id`，无请求 body 或幂等 key。用户界面的显式确认由 W 接线；服务只处理已发出的删除请求。

成功 HTTP200 的 envelope.data 对应 `DeleteInvestigationResponseSchema` / `DeleteInvestigationResponse`：

```json
{"investigationId":"uuid","deleted":true,"billingAuditRetained":true,"mediaCleanup":"not_needed | managed_by_existing_gc"}
```

活动调查（含 waiting_for_user）、追问、伴读/音频任务、watch check、active watch 或此案 sent/reserved 调用均409 INVALID_STATE。其他 session 的 ID 或已删除 ID 返回404 NOT_FOUND；重复删除效果幂等，不新建墓碑表，也不假称第二次仍找到原内容。

在 BEGIN IMMEDIATE 内先校验 owner、活动及在途状态，再按44表现有FK关系清除本案的调查内容、报告、checkpoint、原始模型 trace/receipt、澄清、线索整理、事件、固定版本伴读/问答/音频关联、watch/通知/提交关联、附件索引、原创建幂等记录，最后删除 investigation。异常跨案件版本链接先拒绝，不删除其他案件的关联。

root P 已明确接受的报告保护处理：仅本删除事务暂卸 `immutable_result_delete`，删除本案版本后以原 SQL 恢复；`immutable_result_update` 始终保留。任意错误由 SQLite 连同 DDL 完整回滚，不修改全局 migration 或关闭 foreign_keys。

**保留** sessions 及必要费用审计：usage_ledger、usage_reconciliations、call_pool_reservations、paid_campaign、paid_campaign_calls、budget_pools 完整原行不变，包括 used/reserved、unknown、金额、次数、paused 和关联 case/run ID。删除不退款、不释放未知费用、不重置额度。任务派发/提交记录属于随案删除的派生关联，不作为费用账本保留。

private_assets 索引及其引用清除后，物理私有文件由既有 UUID 限定的孤儿 GC 回收；删除实现不执行任意文件删除或递归路径操作。存在资产时响应 `managed_by_existing_gc`，**不承诺当场清除全部物理文件**；没有资产索引时 `not_needed`。已有备份/用户导出不由此 API 删除。
