## 修复与失败回归

### 1. 开发代理白屏

Vite 以 `src/web` 为 root，开发浏览器导入 `/api/client.ts` 等模块；原 `/api` 前缀代理将它们发给 Fastify 并返回404，因此 main 模块图无法加载。先新增实际 Vite + Fastify + Edge 回归，`/api/client.ts` 期望200实际404，明确 RED。

用户本条消息直接授权了唯一公共文件例外 `vite.config.ts`。仅将代理 key 改为 `^/api/v1(?:/|$)`，目标端口不变，保留 `/health`；不改重写、Origin、cookie 或服务器路由。参考 [Vite 官方 server.proxy](https://vite.dev/config/server-options#server-proxy)：普通 key 做前缀匹配，以 `^` 开头按正则处理，匹配后不经 Vite 转换。正则兼顾 `/api/v1` 根与子路径，不误匹配 `/api/v10` 或前端 `/api/*.ts`。

回归检验四个真实开发 ESM 模块返回200/JavaScript，`/health/ready` 到达 Fastify，未登录 `/api/v1/session` 返回实际401/UNAUTHENTICATED。新测试最初误将未登录接口写成200/null，已依据现有 API 修正为401，没有修改生产接口迎合测试。

### 2. 旧报告遮盖新任务停止 / 错误追加预算

实际浏览器：先得到受控到限报告V1→点追加一轮启动R2→停止R2。旧 `hasResult` 分支将 cancelled R2 显示成V1到限页，“继续调查”不存在，用户只能再次 add_budget。先写浏览器回归，缺少“继续调查”而失败。

修复：最新取消/失败/中断任务若无自身新报告，在旧报告上方独立显示本轮状态，恢复明确传当前 run.id；保留旧报告/引用/复制，不能用旧报告表示本轮完成。outcome 只接收同一个 run 的状态。后续复审发现R3完成但仍显式选旧到限V1时，旧追加按钮还会把预算加给新R3；新断言“此时追加一轮=0”先观察实际1而失败，再收紧为**有当前 run 且与报告 runId 一致、恢复完整**才开放追加动作。

同一浏览器回归证明：取消前后刷新恢复、已有旧正文可读、动作序列恰为 start/add_budget/resume、resume 保持R2预算窗口、调用3次受控业务、出现新版本提示后旧正文仍保留，明确点击“看新版”才切换。

### 3. 澄清失败反馈与提交状态

等待澄清时控制器已记录401/409/503或输入校验失败，但 UI 分支未渲染错误，表现为点击无反应。先用真实后端等待澄清、浏览器局部注入受控503，断言 role=alert，实际找不到而失败。

修复：保留回答并显示安全错误、提交/恢复期间禁重复点击、输入上限对齐现有2000；canProceedWithUnknown=false 时不再写“不问也能查”。unknown 只在 recovering 说“正在只读核对”，恢复结束仍 unknown 时不谎称后台继续读取；提示保留回答、核对状态再决定重试。回归包括503→用户明确再试时断网→只读恢复而不自动重发→再次明确提交成功，受控错误不会清空答案。

### 4. 证据链遗漏限定与理由

卡片原本只显示命题/事实状态/摘录，遗漏 claim.conditions、claim.reasonSummary、link.rationale。truth adapter 会将部分条件汇总到全局，但多命题条件仍无法一一对应。先以真实 ResultView 服务端渲染观察专属条件缺失而失败，再补只读显示三类已有字段；沿用原有变量增加一条排版规则，不改 payload、引用、时间或判断。

独立只读复审确认以上问题及补充修复，无新增 Critical/Important；该审查不代表用户视觉确认或事实语义质量验收。
