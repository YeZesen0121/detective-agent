## 已实现的内部能力

RunStore复用宿主持有的SQLite连接；构造时没有恢复或调用副作用。迁移003增加runs、run_submissions、run_checkpoints、progress_events；001/002数据保留。

- `enqueue`：普通start/resume，使用已存在且归属正确的window预算池。不会自动授予预算、追加额度或接收watch。start只允许draft；resume只允许最近cancelled/interrupted任务，复用原窗口和材料，建立新run。
- 同一session/key同内容返回原run，即使原run后来取消也不重开。不同内容409；案件部分唯一索引阻止不同key同时创建两个活动run。提交与事件在同一立即事务内。
- `claimNext`：按持久ordinal原子领取最早queued任务；多进程只领取一次。该能力不是已启动的后台队列工作者。
- 取消、等待用户、继续均持久更新epoch；旧worker不能写材料或事件。`assertCurrent`可供PaidGateway注入，核对归属、预算窗口、访问组、scopeVersion和活动run。普通run守卫明确拒绝watch/交互上下文。
- 活动区间从领取开始，等待用户时关闭，继续时另开；排队与等待不计入run.activeMs。重启使用恢复时间关闭未结束区间，保守计入无法区分的停机时间，不冒充精确测量。
- checkpoint按Run持久保存；patch内出现的数组是该类别的完整修订，其余类别保留。恢复复制材料，新run之后修改不影响旧材料。材料以WorkingMaterialSchema校验，并限2MiB；正式结果引用闭包/语义核验仍属于后续snapshot提交。
- 事件由平台分配案件内递增seq；公开读取有归属检查、游标和最多100条分页，只返回public。平台生命周期消息由状态转换生成，worker不能伪造完成/取消事件。
- `interruptOnStartup`仅由单实例宿主启动、派发前显式调用；queued/running转interrupted，waiting_for_user保留。没有自动付费重放。账本`recoverInFlight`仍由宿主另行调用。
