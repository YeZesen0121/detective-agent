## 2. 技术选择与运行边界

|选择|理由|代价与验证|
|---|---|---|
|TypeScript 贯通前后端|共享类型与校验，减少 Agent 之间字段翻译|仍需运行时校验，类型通过不代表语义正确|
|React + Vite，Fastify API|本产品无需优先做 SEO/SSR；前端可构建为静态资源，由同一后端提供|G0 固定兼容版本、开发代理与生产同源行为|
|SQLite + better-sqlite3，SQL migration|单实例小规模，少一个数据库服务；便于事务控制预算和快照|原生依赖要在 Windows/Linux 验证；数据库操作短事务，网络调用不放事务内|
|常驻 Linux Docker 服务 + 持久卷|容纳调查任务、调度与持久数据，避免函数执行时间成为主限制|服务器/HTTPS/域名或平台地址尚无，必须当日早验证；不报价或自动购买|
|单进程任务队列，数据库记状态|无需引入分布式队列；有限并发符合比赛规模|只运行一个服务副本；退出时停止新任务，重启后未完成普通 run 标 interrupted，不盲重放收费调用|
|前端轮询增量事件|实现与断线恢复简单，结果不依赖长连接|起始约 2 秒，仅活跃页面轮询；后台任务独立。若更改为 SSE，保持同一事件契约|

SQLite 开 WAL 和 busy_timeout；持久卷同时保存数据库、附件、受控音频缓存。部署不能用临时盘。服务重启对盯梢释放过期检查租约，记录中断，不把重放计作新事实变化。

供应商工程候选：元宝 SearchPro、DeepSeek 文本/视觉及 Fetch、腾讯预置音色 TTS；按[API核查](../API与成本核查.md)官方链接重新验证并做最小真实探针。TTS 未开通时可用浏览器声音验证播放交互，但不能据此宣布云音色要求通过。

技术资料核对于 2026-10-24：[Node LTS](https://nodejs.org/en/about/previous-releases)、[Vite Node 要求](https://vite.dev/guide/)、[Fastify LTS](https://fastify.dev/docs/latest/Reference/LTS/)、[better-sqlite3](https://github.com/WiseLibs/better-sqlite3)。这些支持选型判断，不等于本机兼容性已通过。

## 4. G0：并行前必须统一的底座

先给 G0 的接口与可编译骨架约 45–90 分钟时间盒，为工程估计，不是已测工期；完整平台能力另行并行交付。G0 超时优先减少底座复杂度，不能让队友各自造第二套底座。账号开通、正式部署和下述平台行为测试的全部实现不是分支开工前置，但相应能力进入真实集成前必须通过。

**文件职责：**
- `src/shared/contracts.ts`：PRD 第10节所有跨模块实体及枚举、Zod schemas；导出类型从 schema 推导。
- `src/shared/ports.ts`：调查、存储、预算、工具、伴读与调度模块间接口。
- `src/shared/fixtures/`：success、conflict、insufficient、provider-failure、updated-version 五类受控夹具，显著注明合成。
- `src/server/platform/`：会话/访问组、仓储、预算预留结算、后台队列、事件存储、路由外壳。
- `migrations/001_initial.sql`：数据库与唯一约束，由 D 独占修改。
- `package.json`、`package-lock.json`、`tsconfig*.json`、`vite.config.ts`、`Dockerfile`、`.github/workflows/ci.yml`：统一构建/验证/部署。
- `docs/接口契约.md`：从实际 schema 与路由整理契约；包含例子、错误码、版本与变更记录。

**G0 必须做出的决策：**
1. 时间统一 ISO8601 UTC 存储，前端按 Asia/Shanghai 显示；金额以整数微元记账，供应商请求 id 与内部调用 id 分开。
2. ResultVersion 自包含当时的 claim/evidence/source 快照；所有关联 id 必须能在本版本内解析。后续抓取不改旧正文/摘录；更新关联单独维护。
3. HttpOnly 会话 cookie 识别浏览器，体验码仅换取访问组；服务端从会话得到 owner，不接受请求体自报所有者。
4. 调用前账本原子预留额度；调用后结算；超时保留未知成本。A/C/D 的外部付费调用必须经同一入口，不能私自绕过。
5. 普通任务、盯梢检查都走同一调查入口；presentationMode 不进入降低研究质量的判断。
6. 新增、继续、追问、立即检查均具备作用域内幂等键。一个 investigation 同时最多一个活动 run；同一 watch 最多一个活动 check。
7. 分清续跑原预算与用户明确追加预算；追问仅解释已有证据时不重搜，需新事实时由 A 返回同案补查或另开案件的决定。
8. 每个付费调用入口、全局并发、普通 run 与 watch 周期预算、文件大小和请求总量有配置及默认值；缺配置不能视为无限。具体 token/读取/TTS 配额由 D 在 G0 定值，联调后带记录调整。

**最小跨模块入口（语义约定，G0 用实际 schema 落成精确 TS 签名）：**
- `runInvestigation(input, services, signal)`：输入 scope、基本模式、已有证据、run 预算引用；通过 services 输出事件/保存阶段资料；返回结论草案与停止原因，D 校验后提交快照。
- `answerFollowup(input, services, signal)`：返回基于旧证据解释 / 同案补查需求 / 建议另案三类之一；不得自行重置预算。
- `extractAttachments(input, services, signal)`：逐 attachmentId 返回提取与关键歧义；不直接判真假。
- `buildCompanion(input, services, signal)`：消费指定不可变 ResultVersion，产出带 evidenceIds 的主线段落。
- `replyCompanion(input, services, signal)`：回答打断、保留游标、必要时返回补查意图；不自行调用另一套搜索。
- `synthesizeSegment(input, services, signal)`：按供应商限制切段，返回受会话访问控制的音频标识；缓存至少覆盖正文/音色/语速。
- `compareVersions(previous, candidate, services)`：返回有意义变化 / 无有意义变化 / 待核验；待核验不覆盖 baseline。

**HTTP 面向前端的最小能力：** 体验码换会话；上传/读取附件；创建调查；查询调查/run/增量事件；回答澄清、停止、继续、追问；查询版本与历史；伴读启动/推进/打断及音频；watch 创建/列表/暂停/删除/续开/限频检查；通知列表/已读。D 在 G0 统一 URL、请求/响应与错误格式，B/C 不先猜 route。

## 5. 同时推进但不阻塞调查引擎的规划

- 入口、调查中、结果、伴读、历史更新的布局与中文信息层次；先评审一条代表性案件，再扩展。
- 一个小型 DESIGN.md：视觉意图、主题变量、证据状态表达、组件规则、移动端；依据用户独立UI会话的确认结果，由用户侧唯一前端实现Agent维护。
- 伴读用词、固定侦探形象、3–5 段的节奏与预置音色；不改变事实状态与结果快照。
- 用真实探针校准模型 token、正文读取、盯梢周期和 TTS 成本；已确认上限不取消。
- 真实演示案例、试用者安排与录屏。尽早开始，避免最后才发现来源打不开。

先不花时间做关系图、角色编辑器、OJO 全站生成、复杂动画和长篇重复技术说明；这些不影响保留必交范围。

## 7. GitHub 协作规则

- 默认建议私人单仓库。完整版权参考归档不因参赛自动公开；源码快照保留许可证，用户截图与私人测试数据不进入公开材料。
- main 随时可运行；D 是唯一集成人。feature 分支短寿命、每个可验证增量一个 PR，不等模块全部完成。
- 分支建议：`feat/foundation`、`feat/investigation`、`feat/web-workbench`、`feat/experience`、`feat/watch`。
- 共享 schemas、ports、migrations、依赖与 lockfile 由 D 修改。队友提出契约变更 → D 小 PR 合并 → 所有人同步 → 再使用新字段。
- 队友不得顺手修改邻居目录；涉及跨模块变化在 PR 中标明依赖，统一协调所有权。
- 每次 PR 必须写：功能变化、对应 AC、测试命令/结果、真实或夹具、已知限制、接口变更。UI 附桌面/手机截图。
- 合并前同步最新 main，重新运行 typecheck/test/build 和本模块相关 e2e；D 再验证受影响的完整用户路径。CI 使用夹具，不对每个 PR 无限制发起付费请求。
- 数据库 migration 只新增，不改别人已经应用的历史 migration；由 D 编号与解决冲突。
- 发生冲突按共享契约与 PRD 判断，不能直接选择“全部保留我的版本”。不 force-push 共享 main。
- 部署记录 commit SHA 与 schemaVersion；每次合并先做小冒烟。数据库变更前留备份，应用回退不能假设旧程序兼容新 schema。
- Git merge 无冲突不代表语义联调通过；至少做一次端到端、重连、历史版本与真实后台检查。
