## 实施结果与注入入口

上述1–5已在P实现。`experience-ports.ts` 新增P私有 SpeechVoiceBinding / SpeechAuthorizationResolver，`speech-authorization.ts` 实现权威解析；无需迁移或新增公共HTTP字段。完整绑定存入已存在的 `experience_jobs.request_json.voiceBinding`，包含provider/voiceType/revision，并与切段版本一起进入缓存身份；旧任务的幂等键仍只返回原任务，不填假metadata。

宿主 `ExperienceRuntimeOptions` 增加两个可选私有配置：

```ts
// E代码正式接收后由P组装；这里是接口形状，不是默认main配置。
{
  module: experienceTextModule,
  createSpeechSynthesizer, // E导出的 (resolveAuthorized)=>synthesizeSegment
  speechVoices: trustedServerVoiceBindings, // 已核查真实id/provider/voiceType/revision，available:true
  voices: publicAvailableVoiceLabels,
  // providers/pricing/funding/ttsProviderVersion/splitVersion仍须正式注入。
}
```

`createSpeechSynthesizer` 优先于module中的旧语音占位导出；P注入自身resolver。原直接module.synthesizeSegment保持受控测试兼容。factory缺可信metadata时voices为空、health无audio、startAudio返回503，不能因public label存在就假装音色可用。公开voices不返回voiceType/revision/provider。

resolver核对当前持久任务代次/owner/group/deadline；输入必须与job保存的case/version/companion/唯一segment/text/voice匹配，并查固定结果、保存伴读和锁定voice。保存binding必须与冻结的可信服务端配置一致；Abort、配置不符、旧worker、跨owner或改文字均不能合成。解析器不接受HTTP的SpeechBinding自报。
