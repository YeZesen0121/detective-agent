# P3：附件、伴读与音频的平台接入

2026-10-25；P 总集成，基准 `c21bf628bb18e4a6fdaf07d2efd9c006c23c3476`。用户已将任务派发 I/W/E，本轮不等待、不重做各模块、不写 UI。发布 SHA 与合回检查在末节登记。

## 已交付的可接入能力

1. **附件与私有文件。** 007 迁移、真实 multipart 上传、PNG/JPEG/WebP 解码/尺寸/动画检查、案件绑定、顺序/幂等/列表/删除、原图鉴权读取。文件名由 P 生成；只返回公开 Attachment 投影，原始路径和 storageKey 不出 HTTP。原图 sha256 保留，历史报告引用后不能删除。
2. **伴读与问答持久化。** 按报告版本/人物版本复用会话，3–5段输出的引用闭包、游标与已读 claim 保存、显式结束、异步问答状态；新结果只给 updateNotice，旧段落/游标不变。research_request 仍是建议，`newRunId:null`，不隐式发起调查。
3. **独立任务宿主。** 交互队列领取、每案互斥、代次门禁、取消/服务关闭/启动恢复、持久截止时间和活动量累计，浏览器断开不控制任务生命周期。新版本不重置每案池。启动将未结束 job 标记 SERVER_RESTART，已发送 unknown 占用保留，不自动重放；关闭真实生成配置也执行恢复。
4. **音频与缓存。** 服务端从已保存段落取文字，固定音色、provider/split 版本参与缓存键；单缓存 single-flight、字符预留/unknown/已知迟到结算关联同一财务 call_id；块私有保存、manifest、取消、显式新 key 补缺、鉴权单 Range/If-Range。原始 TTS receipt 保存端口已加入可选 services.audio，伪回执/伪 assetId/文字改写/未完整覆盖不能声明 ready。
5. **调查附件链路。** 注入 E.extractAttachments 后，P 在当前研究 epoch 下读取私有图像，保存逐图提取/失败/澄清；I 获得同一批提取。提交重新验证附件集合、归属、顺序、提取文本哈希/摘录、捕获 checkpoint，写 result_attachment_refs。部分图失败须保留未知并降级 partial。未声明截图能力的 profile 在 start 返回 503，不能当作纯文字悄悄忽略。
6. **预算与能力查询。** 新增 interaction-budget 只读接口，无池返回 null，不授予新额度；已配置和剩余限额分别返回。health 不宣称缺模块、transport、版本或音色的音频可用。共享同一个 PaidGateway 执行全局物理并发，经验模块不能绕过网关。

实际路径和对接方法见 [E/W 可直接转发补充](../协作交接/下一阶段/P3-EW平台接口补充.md)，公共 HTTP schemas 位于 `src/shared/experience-http.ts`，注入类型位于 `src/server/platform/experience-ports.ts`。contractVersion 仍 0.1.0；只增加 optional audio 端口，不改旧 I/E/W/M 所有目录或调用签名。gateway callback 增加 callId 参数，原单 signal 回调兼容。

## 限额、参考与取舍

- 上传每案3图/每图8MiB/总24MiB、8192单边/3200万像素；会话96MiB/256文件、进程存储512MiB/4096文件，解码同时2个/最多6等待。未删除的报告原图不为腾空间自动清理，满额明确429。删除只有物理 purge 成功才释放配额，失败保留计数并稍后重试。
- 音频每块2MiB、每段合计32MiB；7天缓存期限，访问和回收时过期不再可读，任务转 partial，只有用户显式新请求才能收费重建。GC 启动/响应后运行，最多每分钟；先提交元数据再清物理文件，孤儿仅清生成 UUID.bin，不扫描用户目录。案件已绑定图片保留以便历史回看；没有暂存未绑定上传入口。文件过期清理不删除历史报告文本。
- 每案交互上限模型30、输入200k/输出30k、活动20分钟、5元、TTS20000字符；每次伴读/问答最多2次模型、累计预留输出2000、活动最长120秒且受全局/组/案件剩余量约束。以上为有限工程上限，**不是新增真实付费授权**；三层资金交集可更小。未知不释放，真实用量超预留则暂停，读取预算同样显示 accounting_paused。恢复最多记到持久截止点，不把停机一小时当活动一小时。
- 真正图像解码采用精确锁定 `sharp@0.35.5`，multipart采用 `@fastify/multipart@10.1.6`，保留原图而不是重编码替换证据。参考 [sharp 安装及运行要求](https://sharp.pixelplumbing.com/install/)、[输入像素及解码选项](https://sharp.pixelplumbing.com/api-constructor/)、[Fastify multipart 流/大小限制](https://github.com/fastify/fastify-multipart)。依赖安装、真实 PNG 解码和 APNG 反例均在本机 Node24 验证。
- 继续 SQLite 短事务＋私有目录，不增加对象存储/队列服务；适合本版单实例，不宣称多机存储或滚动部署可用。媒体请求验证实际文件大小/哈希；音频只做基本 MP3 头、非空和大小检查，不等于完整编码有效性、真实听音或浏览器播放验收。
- 继续已有固定版 ResultVersion/伴读参考原则，P 只做绑定与引用闭包，不替 E 判断全部语义支持或润色质量。图片证据 contentHash 指冻结 visibleText，二进制捕获 hash 另存 Attachment.sha256。真实视觉请求还要求价格侧明确 visionInputTokens 上界，未配不发送。
