## P 的本轮接线

- 异步固定版本追问持久队列、原幂等键恢复、历史列表；路由阶段仅允许 `purpose=followup` 的有界模型调用，禁止自行搜索/读取/写入调查材料。
- 解释沿该版本证据，引用 ID 由平台校验；语义支持与完整性仍是 I 接收门，schema 通过不代表答案正确。
- 同范围补查只由普通调查宿主执行，传入原追问、固定 baseline 与已有 checkpoint，复用原研究窗口；重新检查 stale/活动任务/余额。
- 取消后 resume 保留追问和原窗口；明确 add_budget 才建新窗口。旧版 stale 失败不能用旧 checkpoint 另发一份 partial 覆盖当前版本。
- 解释和伴读共用同案交互池/epoch，互斥领取；重启/关闭记录中断，已发未知费用保留，不自动重放。
- 路由供应商失败立即 Abort。即使业务捕获异常再次调用也必须被门禁挡住。

## 真实验收不能只记 HTTP 成功

至少分别记录复合目标、有效时间冲突、模糊候选、完整解释→同案补查→新版本链的：原问题/确认范围、目标覆盖、实际来源与摘录、支持/反证/条件、关键未知、继续/停止依据、请求次数和成本。人工抽核回答是否被材料支持、是否答全、是否仍应继续。采用20元/100次合计硬边界，固化持久门之前本轮不发真实业务请求。
