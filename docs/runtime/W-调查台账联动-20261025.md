# W 调查台账联动修复

- 用户直接派发：切换案卷、调查阶段或页面时，调查台账内容/状态需要同步。
- 基准：0ed21e8；独立 checkout `ledger-sync`，分支 `codex/ledger-sync`。
- 本批唯一写者为当前会话；范围 `src/web`、`tests/ui`、相关 `tests/web-model` 与本记录。无公共契约、后端、依赖、视觉主题修改，不接管其他 W checkout。
- 根因：台账无页面上下文；说明固定；事件与预算始终来自当前任务，即使正文正在展示其他报告版本。
- 验收：待澄清→继续→终态、调查台↔盯梢、旧/新报告版本、不同案卷隔离、只读错误提示。全部使用 controlled_fixture，真实供应商调用为 0。
- 实现：提取 `InvestigationLedger`，按页面/案卷/当前活动任务/所选报告决定读取目标；活动或新失败/停止任务仍可与旧报告并列呈现，完成后按正在显示的报告读取对应 run。档案读取独立于操作控制器，不改变继续/取消的目标；切换与卸载取消本地读取。说明随真实 run 状态/阶段更新；台账读取错误有提示和只读重试，不重复展示提交错误。
- 红灯证据：原实现澄清时说明仍为固定“开查后”；已保存旧版报告的台账为空。测试初次还有一个按钮 exact 定位错误，已修正后复现真实断言失败，未将该定位失败当产品证据。
- 绿色证据：`npm test` 129文件1201项通过；`npm run typecheck`、`npm run build`、`git diff --check` 通过。
- Edge `ledger-sync`（3项）＋`runtime-states`（2项）＋`media-version-recovery`（2项）＋`media-small-screen`（12项）：最终19/19通过。包含真实本地 HTTP/宿主/SQLite/浏览器，仅业务模块为 controlled_fixture，真实供应商调用0次。
