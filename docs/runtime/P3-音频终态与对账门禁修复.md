# P3 音频终态、对账与子级取消修复

2026-10-25；P 基准 `e69629c6979487bb1b102a856b2526961930f879`。E接入对话报告正式工厂在自己的分支已实现，P只读核对 `53a4b8286d7f837365bda2cfa8fa7b461a24f7be` 的实际签名、speechAttempt和持久音频工厂；本增量不合E源码、不改E/W/UI目录，不改shared/迁移/依赖，也不动主目录工作树。

## 可复现问题及修复

1. **合法失败/取消清单被当作无效输出。** 原 `ExperienceAudio.finish` 仅接ready/partial且强制至少1块；首块失败或主动停止的合法 `{failed|cancelled,chunks:[]}` 会落INVALID_STATE。两个失败回归→修复通过。现接四种终态，仍核对本job/epoch、已保存chunk的完整ID与顺序，伪asset仍拒绝；ready/partial仍要求非空。失败但有已存块则保留为partial，取消仍保留已有块。只保留受限格式 `SPEECH_*` 稳定错误码，任意错误文案归一为AUDIO_FAILED/AUDIO_PARTIAL/AUDIO_CANCELLED，不能透出供应商原始内容。
2. **显式新key在unknown未对账前仍可重复收费。** 原failed/partial/cancelled缓存只要新key就requeue。新增真实SQLite记录回归：字符unknown/财务unknown→拒绝；只对账字符、财务仍unknown→仍拒绝；两者已核对→允许显式重试。换ExperienceStore实例仍受门禁。`ExperienceAudio.create` 在重排/创建新缓存前检查同一伴读段落全部历史语音job的未结请求，换provider/split版本也不能绕过。旧key重放和已完整保存的缓存仍只返回已有状态/字节，不收费。
3. **内部requeue可绕过入口。** 新增同chunk字符预留前的第二道持久门禁，检查自身 `experience_tts_attempts` reserved/sent/unknown 和关联 `usage_ledger` reserved/sent/unknown；未知旧格式chunk_index为空时保守阻止。失败回归→修复通过，第二次attempt未插入。不会把unknown当免费释放，也不做自动对账或重放。
4. **业务子级AbortSignal未进入gateway。** 原服务只使用宿主signal，E的单块20秒child取消会提前返回，但不能中止平台等待/transport。actual HTTP+受控deferred transport先观察child abort后provider signal未中止；合并宿主与本次child signal后通过。model服务同样遵守第三个signal。请求前已abort不发送；请求后abort把字符/财务置unknown、停止提交，物理并发仍由gateway持有，迟到只结算，不能存音频或复活worker。

明确未实现“自动对账”：本次仅提供不可绕过的持久门禁。已知费用/字符由现有内部settle能力核对；真实供应商对账流程、凭证及用户提示还需P后续接线，不能让W用新key当对账。读取已存授权音频不受生成门禁影响。
