# 持续盯梢演示预案

2026-10-24。依据用户Q16、Q19：复用调查流程、有意义变化才提醒；正式默认每小时、24小时有效、最多3项。本文为后续开发及录制预案，尚未实现或实际执行。

## 主演示：真实后台检测受控页面变化

准备公开可访问的团队测试公告页，显著标注“演示活动，非真实报名”。用户查询该测试活动并提供公告URL；调查调用元宝搜索，并读取用户指定的原始来源，形成基线。保存URL供后续周期直接复核。

测试任务采用30–60秒检查周期、最多运行5分钟，界面显示“演示加速：正式默认每小时”。除间隔与到期时间外，使用正式调度、调查、对比、持久化与站内通知代码。测试开关仅供团队使用，不开放给所有试玩者无限加速。

1. 初次检查：测试公告截止时间为A，记录来源、基线、检查时间；首次建立基线不弹变化提醒。
2. 离开产品页面：关闭该浏览器标签，证明调度不依赖前端计时器；另一个窗口修改测试源页面截止时间为B，并附更新说明。
3. 等待后台下一次调度：重新搜索并读取已知原页，比对A与B，核对是同一活动、同一字段、有效更新。
4. 返回网站：看到站内未读提醒；打开可见旧值、新值、发现时间、核验状态和原始来源。
5. 再执行一次检查：内容不变，不重复通知。
6. 补一个不提醒案例：只改页脚时间，关注的截止字段不变；保留检查记录，不发事实改变提醒。

关键限制：搜索引擎不保证几十秒内收录新页面或更新。演示不能依赖即时索引；复用调查时，必须允许复核用户提供／上次保存的原始URL。若该原页无法读取，显示核验失败，不强行演示成功。此案例验证已知来源变化，不冒充已证明发现未知新网页的能力。

## 开放问题的验证与备用材料

对真实公开问题至少留下一次真实元宝复查记录，说明搜索了什么、增加了什么证据、是否值得通知。短时间没发生重要变化也如实显示，不制造新闻。

搜索排名变化、重复转载、新一手证据等情况可以用标明“模拟响应”的夹具验证规则，不能把这部分录像当真实全网查询。

提前录制一份完整的真实后台运行过程作为网络不稳时的备用，标记为历史录制及实际时间。不得展示预制通知冒充实时执行。正式赛事能否接受受控测试页作为进阶材料仍取决于组织方要求；自然发生的外部变化记录若可获取，一并补充。

## 录制和验收证据

保存任务ID、真实元宝RequestId（脱敏）、源页面前后快照／hash、调度时间、原页读取状态、判断结果和通知去重键。录像同时展示输入、加速标识、源页面修改、离开与返回、通知差异和来源点击。鉴权／预算／模型失败不更新已核验基线，也不能算“没有变化”。
