## 方案与取舍

P增加`runtime-backup.ts`和无凭据CLI。备份先取得正式宿主同一把OS独占锁，拒绝运行中宿主；再使用当前锁定better-sqlite3 13.0.3的SQLite backup API保存含WAL的一致副本。不是复制活动中的单个.db。停写期间从副本读取所有未purged私有文件元数据，只复制严格生成键对应的文件，逐字节大小/hash验证，数据库integrity/foreign_key检查通过后才写完成manifest。

恢复先验证完整manifest、数据库hash/schema/私有文件闭包和每个文件hash，只写新目录，不覆盖已有目录/数据库。数据库和`private-assets`目录与正式main默认路径一致；不启动副本worker、不迁移数据库、不载入.env/cookie/供应商配置，不改变原库/额度/unknown。目标被篡改或写入失败时拒绝完成，留下的未完成目录不作为可用备份，程序不自动递归清理。

选择停宿主+同锁而非新增在线文件快照协调机制：当前是单实例小规模，停写能同时避免附件/音频GC与DB快照的竞态，复用已有锁和不可变文件；代价是短暂停服。恢复是新路径，不做危险的就地降级/覆盖；上线前仍须确认应用代码与schema兼容。备份本身含私有用户数据，留本机忽略目录，不发布、不提交Git；凭据需由运行者另行安全配置。

## 命令（主目录运行）

目标父目录先存在，每次选择全新子目录。先核对元数据里的进程/端口归属及无活动任务，停止正式宿主；不要kill全部node。数据库/私有根通过显式位置给定，CLI不读运行.env。

```powershell
npm run storage:runtime -- backup ".local/runtime/overnight.db" ".local/runtime/private-assets" ".local/backups/core-20261025-01"
npm run storage:runtime -- verify ".local/backups/core-20261025-01"
npm run storage:runtime -- restore ".local/backups/core-20261025-01" ".local/restores/core-20261025-01"
```

成功只表示该存储操作完成，CLI输出数据库位置、私有文件位置、schema与文件数；不输出原文、session cookie、key或预算内容。`verify`不需停止主服务；`restore`不覆盖目标。失败退出1，报告安全错误码。备份成功后优先重启原宿主、核对原累计使用与unknown；切换生产到恢复副本必须先确保原宿主停用，不能让两份付费库同时运行。
