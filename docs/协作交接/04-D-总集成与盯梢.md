## 顺序

- [ ] 按总计划G0创建仓库、骨架与统一契约，做平台关键测试；发布可供队友分支起点的commit。
- [ ] 尽早部署最小页面和健康接口；确认数据库/附件持久化、外网和供应商连通；不要等业务全写完才第一次部署。
- [ ] 接入A的第一条真实查询与B的第一条界面，提交与查询解耦，记录工具调用与成本；集成后立即冒烟。
- [ ] 创建watch/周期检查/暂停/删除/续开与限频；从数据库读到期任务，原子领取检查租约，同watch不重叠。删除或暂停后不安排新检查；已发请求可能完成，但不能因其完成而把已停watch重新激活。
- [ ] 调用统一调查引擎；固定网页复核已知URL，开放问题保持开放检索范围。每周期有限预算，额度不足暂停，不动演示预留。
- [ ] 比较有效事实变化；排名、转载、页脚更新不单独触发；失败保存待核验并保留旧基线。变化判定要有来源与条件对齐。
- [ ] 新版本、baseline切换与幂等通知在同一事务完成；唯一键watchId+changeVersion。旧正文/引用/伴读快照不可变，更新提示单独关联；通知目标为新版本。
- [ ] 关闭浏览器完成至少一个真实后台检查；受控公告页真实改值→读取→核验→通知，显著标加速/合成来源。再测失败与重复检查。

## 测试

tests/platform 除G0测试还覆盖：跨会话读取所有资源失败、预算并发与未知成本、进程重启普通run中断/不重复收费、合法公开URL抓取边界与重定向校验（若自抓取）。

tests/watch 覆盖：同周期不重入；首次基线无通知；新证据改变判断才通知；失败不覆盖基线；重复变化无重复；暂停/删除不再调度；到期/余额不足暂停；新旧版本和通知链接；服务器重启过期lease可恢复检查但不盲重放未知收费。

CI运行typecheck/test/build及无密钥夹具e2e。真实API探针与人工引用核对单列记录。不要把旧research样例当成已经通过的测试。
