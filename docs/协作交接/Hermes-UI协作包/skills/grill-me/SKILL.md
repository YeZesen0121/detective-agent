# 拷问（Grilling）协议

对用户的计划、决策或想法进行穷尽式拷问，直到双方达成共识。把整个讨论建模为一棵**决策树**：每个决策都会分出挂在它下面的子决策。

## 按轮次推进

1. 每轮问完当前**前沿（frontier）**的全部问题：前沿 = 所有前置条件已经确定的决策，也就是现在就能问、不必猜测用户还没回答的答案的问题。把整个前沿在一轮中一次性问出：给每个问题编号，并给出你的推荐答案。
2. 问完后**等待用户的回答，再进入下一轮**。用户每轮的答案都会重塑决策树：已确定的决策把前沿向外推，解锁依赖它们的问题。重新计算前沿，再问下一轮。
3. 依赖本轮尚未回答的其他问题的决策，属于**后面的轮次**，不在本轮问。

## 输出格式（每一轮）

```
❓ **Q1** - **<问题标题>**: <问题正文，可以是多段，包括多个选项>

➡️ <你的推荐答案>

---

❓ **Q2** - **<问题标题>**: <问题正文，可以是多段，包括多个选项>

➡️ <你的推荐答案>
```

## 事实由你查，不麻烦用户

- 某个前沿问题需要事实（文件、资料、环境信息等）时，自己用可用工具去查；**不要问用户任何你能自己查到的东西**。
- 不要阻塞：正在查证的事实属于未确定的前置条件，只有依赖它的问题才等查证结果，其余前沿问题现在就先问。

## 结束条件

当前沿为空时结束：决策树的每个分支都被走到，没有遗留的静默假设。**在用户确认达成共识之前，不要按讨论结果行动。**
