## P01：Open Deep Research

**凭什么值得参考：** LangChain 官方研究实现，状态和工具边界明确。源码提供澄清、任务简报、监督分派、研究、压缩、报告生成的可检查流程，能回答“接下来搜什么，什么时候结束”。[固定版本主流程](https://github.com/langchain-ai/open_deep_research/blob/1b7d2e80db9faa586165c60e09096dbbfd483a64/src/open_deep_research/deep_researcher.py#L1-L100)

**读到的实现：** `clarify_with_user` 和 `write_research_brief` 分开；监督工具执行与单个研究者执行分开；最大迭代与研究完成信号共同控制退出。压缩前的完整上下文与最终报告不是同一对象。

**不能照搬：** GitHub 元数据显示已归档，不能继续称它为“持续维护的首选底座”。所读 `supervisor_tools` 异常处理出现 `is_token_limit_exceeded(...) or True`，会让其他异常也走结束分支；这属于静态代码观察，未运行复现。我们的退出原因必须保留为异常／预算／完成，不能统一报成功。

**迁移判断：** 学习明确状态和受限循环即可。直接引入 LangGraph、多研究者和完整报告系统会多出模型兼容、并发预算、持久化适配；本项目未证明这些复杂度必要。API 调用次数必须在真实调用边界计数，不能拿研究轮数代替。

## P02：GPT Researcher

**凭什么值得参考：** 有实际递归调度、来源上下文、解析修复及针对失败的回归测试，和用户要求高度对应。[递归模块](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/gpt_researcher/skills/deep_research.py#L250-L584)

**读到的实现：** 查询携带 researchGoal；研究结果提取 learnings、followUpQuestions、citations；用信号量限并发，按 depth/breadth 下钻。结果聚合保留来源和上下文，而不是只留下自然语言摘要。全部分支失败时停止下钻。

**两条特别有价值的测试：**
- [空结果停止递归](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/tests/skills/test_deep_research_empty_results.py#L12-L55)：模拟全部检索失败，断言只处理顶层查询，没有无意义递归。
- [压缩后保留 URL](https://github.com/assafelovic/gpt-researcher/blob/3582a6841fe7dc801e2a34e34ee408641aea9bce/tests/test_context_compressor_source_url.py#L13-L32)：小内容快速路径也必须正确输出来源，不能变成 Source: None。

**不能照搬：** 深度减少时仍可能对多个分支继续拓展，depth=2 不是总共搜索两次。使用字符串集合去重 learnings，也不能识别同一原始消息的不同转载。其 `run` 把澄清问题填成自动继续研究，不等于真的向用户问过。迁移时要接入我们已确认的追问方案。

**迁移判断：** 借鉴结构化发现、明确分支失败和两条回归性质；不默认导入整套后端、爬虫、向量检索和报告编辑器。当前源码默认并发值为 2，旧宣传中的其他配置不能当作现状或性能保证。

## P03：STORM / Co-STORM

**凭什么值得参考：** Stanford OVAL 的研究实现，问题衍生不是空泛口号：`WikiWriter` 基于历史对话和 perspective 继续问，`TopicExpert` 把问题变成受上限约束的检索词，再基于资料回答。[知识收集模块](https://github.com/stanford-oval/storm/blob/fb951af7744dab086e34962e9bc6fe878e145f83/knowledge_storm/storm_wiki/modules/knowledge_curation.py#L84-L240)

**读到的实现：** 提问避免重复；找不到资料时允许无法回答。Co-STORM 给检索结果补上产生该结果的问题，并统计 query 数量，便于追踪“为什么搜这条”。[grounded QA](https://github.com/stanford-oval/storm/blob/fb951af7744dab086e34962e9bc6fe878e145f83/knowledge_storm/collaborative_storm/modules/grounded_question_answering.py#L16-L90)

**不能照搬：** 百科写作的广泛覆盖不等于事实判定；多角色观点不是多个独立信源。最后默认分支提交在 2025 年，不能因机构知名度说它正在密集维护。已有引用相关 issue 只能说明有人报告问题，不能当作本次复现或最新版本缺陷结论。

**迁移判断：** 按“定义、反例、原始出处、时间变化”生成互补问题；问题缺口来自资料和用户目标。不要复制多角色长对话或整个知识地图工作台。

## P04：Vane

**凭什么值得参考：** 它确实是网页搜索问答产品，源码能串起分类、研究过程、引用及前端，不是只有 README 的 demo。[架构说明](research/code/ItzCrazyKns/Vane/docs/architecture/WORKING.md.txt)

**读到的实现：** Researcher 为速度／平衡／质量分别设 2／6／25 次循环；通过 `emitBlock` / `updateBlock` 增量发出研究步骤和来源；URL 重复时聚合内容。[研究循环](https://github.com/ItzCrazyKns/Vane/blob/348feca3e378fb4157b217724ed508dc707f853f/src/lib/agents/search/researcher/index.ts#L15-L218)。来源组件展示部分来源并可展开更多、点击原页。[来源组件](https://github.com/ItzCrazyKns/Vane/blob/348feca3e378fb4157b217724ed508dc707f853f/src/components/MessageSources.tsx#L26-L159)

**不能照搬：** 它的三档改变调查强度，而用户的简答／证据链／伴读不能改变质量。URL 去重不等于原创来源去重。其过程 UI 包含计划文本；我们应展示可核验的步骤与依据摘要，不把模型内部思维文本包装成事实证据。

**迁移判断：** 学习流式事件和来源交互。整站迁移还牵涉原搜索后端、模型接口、会话与 widgets；当前没有证据证明比小型专用实现更快。证据卡和图的取舍仍待用户确认。

## P05：Jina node-DeepResearch——强相关，但有与本产品冲突的规则

**凭什么值得参考：** 有搜索、阅读、改写、引用、评估和 token 计数的实际分工，适合研究“简短答案背后的多步调查”。[Agent](https://github.com/jina-ai/node-DeepResearch/blob/fd323b521a51264d497bec333bfb997da1bf3210/src/agent.ts#L804-L986)

**值得借鉴：**
- 先搜索，再利用结果片段改写；去掉已经搜过的查询。
- 搜索之后暂时禁用立即作答，推动访问网页而非仅依赖摘要。
- 保留访问过／失败的 URL、知识缺口及 token 用量。
- 引用构建关联已获取的网页文字与 URL，优于随意生成网址。[引用构建](https://github.com/jina-ai/node-DeepResearch/blob/fd323b521a51264d497bec333bfb997da1bf3210/src/tools/build-ref.ts#L287-L304)

**明确不采用的四处设计：**
1. [definitive 评估](https://github.com/jina-ai/node-DeepResearch/blob/fd323b521a51264d497bec333bfb997da1bf3210/src/tools/evaluator.ts#L49-L70) 把“不知道、信息不足”等表达列为不通过；分类提示又倾向要求大多数问题进行这项检查。与我们的“不装懂”原则冲突。
2. [Beast Mode](https://github.com/jina-ai/node-DeepResearch/blob/fd323b521a51264d497bec333bfb997da1bf3210/src/agent.ts#L197-L209) 以及预算后的强制作答路径，不适合作为证据不足时的兜底。我们应输出部分结论和明确未知。
3. [查询改写](https://github.com/jina-ai/node-DeepResearch/blob/fd323b521a51264d497bec333bfb997da1bf3210/src/tools/query-rewriter.ts#L14-L62) 要求推断用户潜意识、隐秘动机，并固定多个视角。我们只扩展与任务有关的检索角度，不揣测用户心理或无条件制造七条查询。
4. freshness 提示中的通用天数阈值没有成为本项目规则的依据；新网页可能报道旧事件，较旧的官方说明也可能仍有效。

**迁移判断：** 选用动作分工与读原文约束；重写目标函数和退出逻辑。它依赖其他阅读、重排／去重服务，替换一个 search 函数不等于完成元宝适配。我们没有运行它，也不声称它实际一定产生幻觉。

## P06：changedetection.io

**凭什么值得参考：** 长期围绕网页变化监测构建，具体到正文过滤、配置哈希、差异、意图判断、缓存和预算；有对应测试。

**读到的实现：** 文本处理器支持 CSS/XPath/JSON 范围、忽略内容、触发词；选择器没有匹配到内容会报错。规则配置进入 hash，配置变化需要重新考虑基线。[处理器](research/code/dgtlmoon/changedetection.io/changedetectionio/processors/text_json_diff/processor.py.txt)

[意图评估](https://github.com/dgtlmoon/changedetection.io/blob/352b036217e32d3622f282f49bebcdb89592a28c/changedetectionio/llm/evaluator.py#L891-L989) 以 intent+diff 做缓存，空差异不触发；预算用完或模型失败则采用 fail-open，放行重要变化通知。[测试](https://github.com/dgtlmoon/changedetection.io/blob/352b036217e32d3622f282f49bebcdb89592a28c/changedetectionio/tests/llm/test_evaluator.py#L284-L358) 包含空 diff、缓存跳过调用、失败放行。

**不能照搬：** 放行通知可以避免漏报，但不能把未核验变化说成“事实已确认改变”。本产品应区分“检测到内容变化，尚未核验”与“已核验触发条件”，模型失败另标状态。

**迁移判断：** 固定网页盯梢的首要机制参考；开放问题仍需自己的检索、去重、证据状态比较。整套自托管会增加进程和浏览器依赖，比赛首版不默认引入。

## P07：PaddleOCR

**凭什么值得参考：** 专门的 OCR 工程，所读接口明确支持文字识别阈值、文本行方向、文档方向／矫正和词框输出，可用于检查截图定位与数字。[OCR pipeline](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/paddleocr/_pipelines/ocr.py#L179-L237)

**边界：** 识别得分衡量文字识别，不是图片中命题真实程度；词框也不是可靠来源链接。此次没跑中文截图、图表或低清识别评测，不写胜过视觉模型的结论。

**迁移判断：** 先测已有视觉 API；低清密集文字反复失败且确需坐标时，再评估轻量 OCR 或托管服务。有限开发时间内不自托管完整文档智能流水线。

## P08：ALCE

**凭什么值得参考：** 引用质量有公开可检查的评价代码，补上“带链接仍可能乱引”的盲点。[评价实现](https://github.com/princeton-nlp/ALCE/blob/246c476a4edfc564266b7346b6e29ef4861ae937/eval.py#L350-L428)

**读到的实现：** 拆句、取引用、检查索引越界、让 NLI 检查引用集合能否支持句子，再检查多引用中是否夹带不必要材料，输出 citation recall / precision。

**边界：** 这是研究评估仓库，最近提交较早，不是可直接部署的侦探 Agent。自动蕴含判断自身会错；文档能支持一句话，也不保证文档说的现实事实就为真。

**迁移判断：** 人工验收中分别检查“关键事实有没有引用”与“引用是否支持该事实”。不要把 citation 分数显示为真实概率，也不在黑客松部署其大型评估模型。

## P09：React Flow / xyflow

**凭什么值得参考：** 成熟的节点和连线交互组件；所读 Layouting 示例具体实现节点／边状态、箭头、视图适配和 dagre 布局。[官方示例](https://github.com/xyflow/xyflow/blob/8523d8dd9f1551954bc221dccabd6a3119ef9e22/examples/react/src/examples/Layouting/index.tsx#L24-L119)

**边界：** 它负责画图，不知道何为证据。默认示例允许连线、拖动、编辑；我们的只读结果图不应允许用户无意改变事实关系。布局尺寸、长中文、移动端、点击节点看原文都仍需实现和验收。

**迁移判断：** 若用户选图，采用组件比手写缩放画布合理；若选卡片则无需添加依赖。MIT core 不代表所有付费模板或 Pro 内容都可任意复制。

## 不纳入的类别与证据缺口

- 没找到经本轮核实、能直接覆盖“三基本模式＋证据裁决＋侦探伴读＋开放盯梢”的成熟一体项目；不会为了凑数推荐小仓库。
- Socratopia 是体验参照，官方原版开源仓库未核实；名称相似的非官方复刻不作为原版源码或成熟度证据。
- 各种只包装一次联网 prompt 的工具，没有提供本项目需要的来源／失败／预算机制时不列入推荐。
- 图像伪造检测、反向搜图、实时双向语音不是本次已验证能力。
- 所有建议还需使用元宝真实返回及开发目标模型做集成验证。许可证仅核对所引用仓库根 LICENSE；实际复制时仍要检查具体文件、依赖、素材权利并保留所需声明。
